# keklib-cli

## Назначение
Локальный CLI: поиск в обновляемом INPX, выбор книги по номеру, безопасное извлечение одного FB2. Целевые ОС — Linux, Windows, macOS; поставка — portable standalone PyInstaller onedir, без установки Python пользователем.

## Обязательные модели и способ исполнения
Пользователь явно закрепил роли. Это правило сохраняется при продолжении сессии, compaction и переходе между задачами:
- Исполнение: `subagent-driven-development`, свежий implementation subagent на задачу.
- Все implementation subagents, исправления и повторные попытки: **`zai-coding-plan/glm-5.3`**.
- Все review subagents: проверка задачи, scoped re-review, preflight и финальный обзор: **`openai/gpt-6.1-sol`**.
- В каждом вызове subagent указывать model явно. Не использовать варианты Flash, Highspeed или Fast и не заменять модель по умолчанию.
- При недоступности модели или необходимости иной модели остановиться и запросить разрешение пользователя; автоматическая смена при escalation запрещена.
- Implementation/review subagents сами не запускают других subagents. Отдельный reviewer запускается только координатором.

## Инварианты
- Исходные INPX/ZIP только читаются. Реальная библиотека — внешний пользовательский ресурс, не fixture и не место записи проекта.
- Config/cache используют нативные пользовательские пути и никогда не каталог executable.
- Общая блокировка живёт до закрытия SQLite-читателя; писатель требует исключительной блокировки. Не заменять открытую читателем базу, не удалять её перед атомарной заменой.
- Извлечение только одного точного ZIP/member; CRC, безопасное переносимое имя, атомарная публикация без перезаписи. Запрещён extractall.
- Никаких заявлений о Windows/macOS по одним Linux/mock-тестам; готовность portable требует проверки executable в изоляции на его ОС/CPU.
- Не создавать remote repository, не push/merge/publish и не запускать платную инфраструктуру без отдельного разрешения.

## Структура и текущий этап
Реализованы контракты данных, основа CLI, нативные платформенные
операции, потоковый импорт INPX с объединением серий (включая завершающий
`\x04`-разделитель реальных строк Lib.rus.ec), хранилище
поискового индекса SQLite FTS5 с нормализацией текста, индексатор
с проверкой свежести и атомарной пересборкой, поисковая сессия под общей
блокировкой с устойчивыми страницами, чтение точного файла книги из ZIP
с повторными проверками, запись на диск с переносимым именем и атомарной
no-replace публикацией (задачи 1–8), команды CLI с нумерованным
терминальным интерфейсом (задача 9) и нативный сквозной TTY-тест с
приёмкой реальной библиотеки (задача 10): POSIX PTY-harness
(`tests/harness/tty.py`), интеграционные тесты реального module CLI
(`tests/test_integration.py`) и инструмент приёмки
`tools/verify_library.py`. На текущем Linux приёмка выполнена на реальной
библиотеке (421 ГБ, 230 архивов, INPX 34 868 212 байт, 470 352 книги,
индекс 369 278 976 байт: постройка 10,199 с, повторная валидация 0,422 с,
запрос «Булгаков Мастер» — 0,001 с, пиковая RSS 59 240 KiB) с точной
известной парой `fb2-060424-074391.zip`/`66372.fb2`; источники побайтно
неизменны (INPX и выбранный ZIP сверены SHA-256, остальные архивы — только
lstat-снимок, содержимое всех ~451 ГБ не читалось). Реализован конвейер
portable-упаковки (задача 11 + fix rounds 1–3): `packaging/` (entry/spec/
targets/toolchain/lock/уведомления + манифест лицензионного закрытия
схемы 2 и приложенные тексты) и `tools/build_portable.py` с 48 тестами
`tests/test_packaging.py`; гейты (все fail-closed): preflight toolchain
по пинам, glibc-гейт по семантике ELF (динамический сегмент с
обязательной полнотой таблицы и DT_NULL — пустой/усечённый/
незавершённый сегмент не даёт «нет требований», отдельное распознавание
4-байтового ELF-magic как усечённого ELF; иначе секции SHT_GNU_verneed
по типу безотносительно имени; строгие цепочки/границы; неподтверждаемые
ELF, неизвестные маркеры и GLIBC_PRIVATE — отказ; RELR учитывается как
2.36; провайдер не скрывает GLIBC; независимая сверка с readelf),
release-гейт метаданных (null SQLite-pin блокирует выпуск), лицензионный
гейт по рекурсивному фактическому инвентарю (относительные пути,
расширение или ELF-magic, контракт компонентов/покрытия со строгим
bool `distribution_ok`), полный обход дерева с containment
ссылок/reparse (tar — относительные ссылки, zip — материализация
внутренних целей, внешние/битые/покидающие запрещены) и протокол пары
архив+сумма без удаления архива с явной операцией ремонта суммы.
Фактический нативный прогон `linux-x86_64` на текущем dev-хосте
(CachyOS, glibc 2.44) прошёл onedir-сборку и самопроверку executable,
