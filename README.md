# keklib-cli

> [!WARNING]
> **Этот проект полностью вайбкодерский.**
> Код, тесты и документация создавались ИИ-агентами под руководством человека. Наличие тестов не гарантирует отсутствие ошибок. Используйте проект с пониманием этих ограничений.

Локальная консольная утилита для поиска книг в собственной библиотеке
Lib.rus.ec: читает обновляемый каталог INPX, строит поисковый индекс и
позволяет выбрать книгу по номеру в интерактивном терминале и извлечь
ровно один FB2 — существующие файлы не перезаписываются. Книги никуда
не скачиваются: исходные INPX/ZIP библиотеки только читаются.

- [Установка](INSTALL.md) — portable-архив: работает без установки
  Python (Python нужен только разработчикам или для запуска из
  исходников).
- [Сборка и тестирование](BUILD.md) — конвейер portable-сборки,
  проверенные команды и честный статус по платформам.

## Быстрый старт

Библиотеку вы предоставляете сами (локальная копия Lib.rus.ec: INPX-каталог
и ZIP-архивы книг). Корень библиотеки указывается один раз, при первом
запуске `setup`; `search` требует интерактивного терминала: программа
печатает пронумерованные страницы результатов, книгу выбирают вводом
номера, извлечённый FB2 сохраняется в `--output` (по умолчанию `~/Books`).

Portable-версия (установка — в [INSTALL.md](INSTALL.md)):

```bash
keklib-cli setup --library "/путь/к/библиотеке"
keklib-cli search "Булгаков Мастер"
keklib-cli search "Мастер и Маргарита" --output ~/Books
keklib-cli index --refresh
```

`index --refresh` принудительно перестраивает индекс после обновления
библиотеки; обычно пересборка происходит автоматически при первом поиске.
Форма запуска из исходников — та же команда через
`.venv/bin/python -m keklib_cli` (см. [BUILD.md](BUILD.md)).

## Статус

Публичного релиза пока нет. Проверено фактически (Linux):

- локально собранный и принятый portable-архив **linux-x86_64**:
  воспроизводимая сборка в rootless-контейнере на Ubuntu 22.04.5
  (glibc 2.35, CPython 3.14.8, SQLite 3.54.1); все гейты сборки
  Linux-архива (`tools/build_portable.py`) пройдены, включая нижнюю
  границу glibc 2.35;
- изолированный smoke frozen-executable в userspace-контейнере
  Ubuntu 22.04.5 / glibc 2.35: полный TTY-сценарий (setup, поиск с
  выбором номера, обновление INPX, повторный поиск), состояние вне
  комплекта программы, источники неизменны — заявленный минимум
  подтверждён нативным прогоном;
- приёмка на реальной библиотеке (421 ГБ, 230 архивов, 470 352 книги):
  постройка индекса ~10 с, повторная проверка без пересборки < 1 с,
  поисковый запрос ~0,001 с; SHA-256 INPX и выбранного ZIP до/после
  совпали, остальные архивы проверены только lstat-снимком —
  содержимое всей библиотеки не читалось.

Windows и macOS — целевые платформы сборочного конвейера, но их нативные
сборки и CI-прогоны не завершены (SQLite-пины этих платформ не
инвентаризованы и блокируют выпуск), полного выпуска на все четыре
target нет. Работоспособность на Windows 10/11, старых выпусках macOS
или произвольных Linux-дистрибутивах не заявляется. Контрольные суммы
и подробности — в [BUILD.md](BUILD.md) и [INSTALL.md](INSTALL.md).

Первый прогон публичного source CI (2026-10-19) упал на всех шести
jobs матрицы Linux/Windows/macOS × CPython 3.11/3.14; установленные
причины исправлены в этой же волне (зависимость тестов сборочного
tooling, канонизация U+FFFE/U+FFFF/суррогатов в лексике поиска,
константа Darwin `RENAME_EXCL`, координаты tar-ссылок и переносимость
тестов). Нативный повторный CI на момент правки не выполнялся — его
зелёный статус не заявляется. Принятый Linux-архив выше при этом
остаётся предыдущей ревизией продукта и пересборке в этой волне не
подвергался.
