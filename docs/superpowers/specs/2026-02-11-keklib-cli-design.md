# Спецификация CLI для поиска и извлечения книг

Статус: пересмотренная спецификация подтверждена пользователем, включая Linux/Windows/macOS, portable standalone и корневые инструкции/`AGENTS.md`. План реализации подготовлен отдельно и ожидает проверки пользователем.

## 1. Цель и согласованные требования

Создать локальную утилиту `keklib-cli` для сценария: поисковый запрос → список книг → выбор по номеру → извлечение выбранного FB2 из ZIP.

Пользователь подтвердил:
- Нумерованный список с вводом номера, без полноэкранного TUI.
- Возможность дальнейшего пополнения INPX новыми книгами.
- Python 3 и SQLite с полной пересборкой индекса при изменении INPX.
- Автоматическое обновление индекса, сохранение старого индекса при неудаче и неизменность исходной библиотеки.
- Название команды и дистрибутива — `keklib-cli`, Python-пакет — `keklib_cli`; каталоги состояния также используют `keklib-cli`.
- Полноценная нативная работа в Linux, Windows и macOS: настройка библиотеки, индексирование, обновление, поиск, выбор по номеру и извлечение. WSL, Wine, Docker и виртуальная машина не считаются поддержкой Windows или macOS.
- Основное распространение — portable standalone: архив с исполняемым файлом и его зависимостями, без установки Python конечным пользователем.
- В корне исходного проекта обязательны `README.md`, `BUILD.md`, `INSTALL.md` и `AGENTS.md`; документация и инструкции составляются на русском языке.

Исходные INPX и ZIP открываются только для чтения. Индекс, конфигурация и извлечённые книги не записываются в каталог библиотеки автоматически.

## 2. Исходная библиотека и среда

Проверенный корень библиотеки: `/run/media/user/Untitled/_Lib.rus.ec - Официальная`.

Структура:
- `librusec_flib.inpx` — ZIP-контейнер с `structure.info`, служебными файлами и отдельными INP.
- `lib.rus.ec/*.zip` — архивы книг; имя INP соответствует имени ZIP с заменой расширения.
- `librusec_mhl.inpx` — альтернативный каталог, не используемый автоматически.
- `flib_additional/` — дополнительные сведения, не обязательные для первой версии.

В исследованном снимке: 620093 записи каталога и 230 ZIP, около 451 ГБ. Все ZIP, указанные каталогом, присутствуют. Это сведения об исследованном снимке, а не гарантия для будущих обновлений.

Проверка активных FB2 выявила 525386 строк, соответствующих 470352 уникальным парам ZIP/member. Остальные 55034 строки повторяют файл книги: различаются только `SERIES`/`SERNO`, либо строка повторяется полностью. Поэтому строка INPX не считается отдельным изданием автоматически.

Исследованная среда этого компьютера: Linux, KDE, Python 3.14.8, SQLite 3.54.0 с FTS5; FB2 ассоциированы с Okular. Это описание локального исследования, а не ограничение целевых ОС.

Целевые платформы — Linux, Windows и macOS. Исходный код поддерживает CPython 3.11 или новее; portable-сборка содержит свой фиксированный Python runtime и SQLite с FTS5. Конечный пользователь не устанавливает Python, pip, PyInstaller или FTS5 отдельно. Наличие FTS5 во включённом SQLite проверяется при сборке и в готовом приложении с понятной диагностикой при неисправности комплекта. Поддержка не зависит от наличия KDE, Okular, Bash или внешнего архиватора. Одинаковый Python-пакет и набор команд используются на трёх ОС; особенности ОС изолируются в платформенном слое. Поддержка устаревших ОС, на которых включённый runtime официально не работает, не подразумевается.

### 2.1. Portable standalone

Основной формат — PyInstaller `onedir`, упакованный в ZIP для Windows и tar.gz для Linux/macOS. Исполняемый файл запускается из распакованного каталога: `keklib-cli.exe` в Windows, `keklib-cli` в Linux/macOS. Каталог с включёнными библиотеками сохраняется целиком; перенос одного executable без соседних файлов не поддерживается. Это CLI, запускаемый из терминала, а не графическое приложение.

Начальная матрица portable-артефактов:
- `keklib-cli-<version>-linux-x86_64.tar.gz`.
- `keklib-cli-<version>-windows-x86_64.zip`.
- `keklib-cli-<version>-macos-x86_64.tar.gz`.
- `keklib-cli-<version>-macos-arm64.tar.gz` для Apple Silicon.

Windows/Linux ARM и universal2 не входят в начальную матрицу; это не ограничивает возможность добавить их позднее. Сборки создаются на соответствующих ОС и целевых архитектурах, локально либо в CI; сборка Windows/macOS из текущего Linux-checkout не считается готовой поставкой этих платформ.

Исходный Python-пакет сохраняется для разработки, тестирования и необязательной установки опытными пользователями. Упаковка не создаёт вторую реализацию логики. PyInstaller и инструменты релиза — сборочные зависимости; их версии, включённый CPython и SQLite фиксируются в конфигурации сборки и описываются в `BUILD.md`. Для Linux явно задаётся и проверяется нижняя граница совместимости glibc; для macOS и Windows публикуются проверенные минимальные версии ОС. Нельзя обещать поддержку всех дистрибутивов Linux или всех версий ОС только на основании успешной сборки.

Для каждого артефакта публикуется SHA-256 и прилагаются необходимые лицензионные уведомления включённых компонентов. В архив не включаются книги, INPX, индексы, пользовательские настройки, секреты и данные локальной приёмки. Конфигурация и кэш по-прежнему находятся в нативных пользовательских каталогах (§5), а не рядом с executable; portable означает отсутствие установки runtime, а не запись состояния в каталог программы.

Обновление первой версии — вручную, распаковкой нового комплекта в отдельный каталог и переключением на него; нельзя смешивать библиотеки двух сборок. Исходная библиотека и пользовательские настройки не заменяются при обновлении. Готовая программа не требует сетевого доступа для поиска или извлечения.

Однофайловый `onefile`, установщики, автообновление, доверенная подпись сертификатом и Apple notarization не входят в первую версию. Техническая ad-hoc подпись, если её требует runtime macOS, относится к сборке и не является notarization. `INSTALL.md` честно описывает возможные предупреждения ОС для неподписанных доверенным сертификатом архивов и проверку происхождения/SHA-256, не рекомендуя глобально отключать защиту ОС.

### 2.2. Обязательные документы в корне проекта

- `README.md`: назначение `keklib-cli`, поддерживаемые ОС/архитектуры, краткий сценарий поиска/извлечения, ссылки на остальные документы.
- `BUILD.md`: требования разработчика, создание окружения и установка сборочных зависимостей, точные нативные команды тестирования/сборки/упаковки для Linux, Windows PowerShell и macOS; расположение результата, матрица архитектур и минимальных ОС, проверка FTS5, smoke-тест готового комплекта и получение SHA-256. Отдельно указать, что эти зависимости не нужны конечному пользователю, и что Python-пакет в CI не заменяет проверку portable-сборки.
- `INSTALL.md`: выбор архива для ОС/CPU, проверка SHA-256, распаковка с сохранением структуры, запуск из терминала и необязательная настройка PATH без прав администратора, указание пути к библиотеке, первый поиск и извлечение, ручное обновление, пути конфигурации/кэша и удаление программы без удаления книг. Примеры отдельно для PowerShell и Linux/macOS. Должно быть явно написано: установка Python не требуется. Этот документ включается и в каждый пользовательский portable-архив вместе с `README.md`.
- `AGENTS.md`: описание проекта для следующих разработчиков и агентов — назначение, структура модулей, утверждённые спецификация/план, команды разработки и тестирования, сборочная матрица, границы платформенного слоя, запрет записи в исходные INPX/ZIP, правила обновления индекса и no-replace извлечения, требования к документации и проверкам всех трёх ОС. Нельзя объявлять Windows/macOS поддержанными по одним Linux/mock-тестам. Документ не заменяет пользовательские инструкции установки.

Все четыре документа создаются в корне будущего проекта, а не только в `docs/` и не в корне архивной библиотеки. Инструкции проверяются на фактических командах готовой реализации; на стадии спецификации они являются обязательными результатами будущих задач, а не обещанием, что сборка уже существует.

Текущий каталог не является Git-репозиторием. Эта спецификация не разрешает создавать репозиторий, проект, worktree или устанавливать зависимости. Место исходного кода согласуется перед реализацией.

## 3. Границы первой версии

Входит:
- Настройка одной активной библиотеки с возможностью последующего переключения.
- Импорт INPX, локальное индексирование и обновление.
- Поиск по автору и названию, постраничные результаты, выбор одной книги.
- Безопасное извлечение одного FB2 в указанный каталог.
- Понятные сообщения об ошибках и отмена без повреждения данных.
- Нативные пути состояния, межпроцессные блокировки, безопасная публикация файлов и тесты на Linux, Windows и macOS.
- Portable standalone-архивы четырёх целевых ОС/архитектур, их контрольные суммы и проверка запуска без системного Python.
- Корневые `README.md`, `BUILD.md`, `INSTALL.md` и `AGENTS.md` согласно §2.2.

Не входит:
- Конвертация в EPUB, PDF или MOBI; автоматический запуск читалки.
- Скачивание книг, изменение архивов, работа по сети.
- Полнотекстовый поиск внутри книг, морфология, исправление опечаток, транслитерация.
- Одновременный поиск по нескольким библиотекам, пакетное извлечение.
- Полноэкранный TUI, аннотации и подборки, инкрементальный импорт INP.
- Однофайловая упаковка, установщики, автообновление и инфраструктура доверенной подписи/notarization.

## 4. Командный интерфейс

```bash
keklib-cli setup --library "/путь/к/библиотеке"
keklib-cli search "Булгаков Мастер"
keklib-cli search "Мастер и Маргарита" --output ~/Books
keklib-cli index --refresh
```

`setup` проверяет корень, наличие `librusec_flib.inpx`, его структуру и каталог `lib.rus.ec/`. Конфигурация сохраняется только после успешной проверки. Полное чтение всех архивов книг не требуется. Первый индекс создаётся при поиске либо командой `index --refresh`.

`search` принимает один строковый запрос. Запрос из одних пробелов или без поисковых токенов отклоняется. Каталог назначения по умолчанию — `~/Books`; отсутствующий каталог создаётся перед извлечением. Параметр `--output` действует только для текущего запуска.

`~/Books` означает `Path.home() / 'Books'` на любой ОС; приложение не полагается на раскрытие `~` оболочкой. Корень библиотеки не привязан к исследованному Linux-пути: принимаются пути дисков Windows, например `D:\Library`, и обычные пути Linux/macOS. Аргументы с пробелами и кириллицей поддерживаются. Инструкции установки и запуска приводятся отдельно для PowerShell и POSIX-оболочек; Bash не требуется для работы приложения.

Результаты выдаются страницами по 20 книг. Для каждой строки показываются номер, автор, название, язык, серии с номерами при наличии и размер. Разные файлы изданий не объединяются. Повторные строки одного файла, описывающие его в разных сериях, показываются как одна книга со списком серий.

Нумерация сквозная в рамках текущего поиска. Доступны `n` — следующая страница, `p` — предыдущая, `q` — выход. Выбор разрешён только по номеру строки текущей страницы; неправильный ввод повторяет приглашение без извлечения. Выбор номера считается подтверждением извлечения; дополнительного подтверждения без конфликта имён нет.

При отсутствии результатов выводится сообщение без приглашения выбора. При отсутствии интерактивного терминала `search` завершается с диагностикой: машинный интерфейс не входит в первую версию. `Ctrl+C` прерывает текущую операцию; EOF в приглашении выбора эквивалентен `q`.

После извлечения печатается абсолютный путь к книге и программа завершается. Индикаторы и диагностика направляются в stderr, список книг и итоговый путь — в stdout.

## 5. Хранение состояния

| ОС | Конфигурация | Перестраиваемый индекс |
|---|---|---|
| Linux | `$XDG_CONFIG_HOME/keklib-cli/config.json`, по умолчанию `~/.config/keklib-cli/config.json` | `$XDG_CACHE_HOME/keklib-cli/index.sqlite3`, по умолчанию `~/.cache/keklib-cli/index.sqlite3` |
| Windows | `%APPDATA%\keklib-cli\config.json` | `%LOCALAPPDATA%\keklib-cli\Cache\index.sqlite3` |
| macOS | `~/Library/Application Support/keklib-cli/config.json` | `~/Library/Caches/keklib-cli/index.sqlite3` |

Пустые и относительные XDG-переменные игнорируются. При отсутствии Windows-переменных используются `Path.home() / 'AppData/Roaming'` и `Path.home() / 'AppData/Local'`. Пользовательские пути нормализуются штатными средствами платформы, без ручного соединения через `/` или `\\`.

- Временная база и блокировка индекса находятся рядом с индексом, не в библиотеке.
- Незавершённый выходной файл находится в каталоге назначения, чтобы публикация не пересекала файловые системы.
- Прочие временные файлы используют `tempfile` и системный временный каталог; `/tmp/opencode` — только предпочтение текущей среды разработки, не путь, зашитый в продукт для всех ОС.

Конфигурация содержит версию формата и абсолютный разрешённый путь корня библиотеки. Метаданные индекса содержат корень, относительный путь INPX, SHA-256 каталога, версию схемы, версию правил импорта и поиска, дату построения и счётчики импорта. Переключение библиотеки инвалидирует прежний индекс.

## 6. Импорт и модель данных

Порядок полей читается из `structure.info`, а не задаётся позициями в коде. Кодировка — UTF-8 с допустимым BOM; строки разделены переводом строки, поля — `\x04`. Неизвестные дополнительные поля допускаются. Отсутствие обязательных полей, ошибки декодирования и неоднозначные записи прерывают импорт с именем INP и номером строки. Не допускается тихое пропускание повреждённых записей.

Минимально требуются `AUTHOR`, `TITLE`, `FILE`, `EXT`, `DEL`. Необязательные отображаемые поля: `LANG`, `SERIES`, `SERNO`, `SIZE`, `LIBID`. Пустой размер отображается как неизвестный; непустое значение должно быть неотрицательным целым числом. Пустые необязательные значения не препятствуют поиску.

В поисковый индекс входят только записи с `DEL`, равным строке `0`, и `EXT=fb2` без учёта регистра. Остальные учитываются в счётчиках исключённых записей, но не показываются пользователю. Если после фильтрации активных книг нет, пустой индекс считается допустимым.

Для записи сохраняются исходные метаданные, нормализованные автор и название, относительный путь ZIP и точное имя файла `<FILE>.<EXT>`. Идентичность книги определяется парой «относительный путь ZIP, имя файла внутри ZIP»; `LIBID` не считается глобально уникальным.

Повторные активные строки с одинаковой идентичностью объединяются, если все поля, кроме `SERIES`/`SERNO`, совпадают. Пары «серия, номер» сохраняются отдельным списком без повторений в порядке появления; полностью идентичные строки не создают новую книгу. Различия остальных полей считаются конфликтом данных и прерывают импорт с указанием обеих исходных строк. Счётчики различают исходные строки, исключённые строки, повторы и уникальные книги. Разные идентичности не объединяются даже при совпадении автора и названия.

Имя INP должно быть простым именем без компонентов пути; соответствующий ZIP ищется только в `lib.rus.ec/`. Поля, определяющие имя FB2, также не должны содержать компонентов пути. Импорт не читает содержимое ZIP книг и не распаковывает INP на диск: строки обрабатываются потоком.

Правила проверки относительных имён не зависят от ОС запуска: запрещены и `/`, и `\\`, абсолютные и drive-relative пути Windows, UNC/device-префиксы, NUL и управляющие символы. Перенос библиотеки между ОС не переносит доверие к абсолютному пути старого индекса: выполняются новая настройка корня и пересборка.

## 7. Актуальность и атомарное обновление

Перед каждым запуском поиска вычисляется SHA-256 текущего INPX. Одна только дата изменения или размер файла не считаются достаточной проверкой. Обновление требуется при отсутствии или повреждении индекса, изменении SHA-256, корня библиотеки, версии схемы или правил импорта и поиска. `index --refresh` принудительно перестраивает базу даже без изменения SHA-256.

Для актуального индекса используется общая блокировка чтения; исключительная нужна только для построения или публикации. Перед открытием SQLite поисковая сессия повторно проверяет метаданные под своей общей блокировкой. Если между первоначальной проверкой и открытием индекс был заменён, используется проверенный актуальный индекс до выдачи первой страницы; если требуется пересборка, блокировка чтения освобождается до попытки получить исключительную. Повышение shared-блокировки до exclusive с сохранением shared-блокировки запрещено во избежание взаимной блокировки.

Алгоритм:
1. Получить эксклюзивную блокировку индексирования; если она занята, завершить операцию с просьбой повторить запуск позже.
2. Повторно проверить актуальность после получения блокировки.
3. Скопировать INPX в локальный временный снимок, вычислив его SHA-256.
4. Прочитать снимок и построить новую отдельную SQLite-базу с поисковым индексом.
5. Проверить целостность новой базы, счётчики и обязательные метаданные.
6. Повторно вычислить SHA-256 исходного INPX; если он не совпадает со снимком, не публиковать базу и предложить повторить запуск после завершения обновления библиотеки.
7. Закрыть новую базу и атомарно заменить ею старый индекс в той же файловой системе.
8. Удалить собственные временные файлы и освободить блокировку.

Межпроцессная блокировка реализуется платформенным слоем: POSIX-блокировки в Linux/macOS и нативные блокировки файлов Windows. Безусловный импорт `fcntl` в общих модулях запрещён; блокировка должна освобождаться ОС при завершении процесса и не требовать ручного удаления «зависшего» lock-файла.

На время жизни поисковой сессии удерживается общая блокировка индекса, полученная до открытия SQLite; соединение закрывается до освобождения блокировки. Пересборка/публикация требует исключительной блокировки. Если читатель ещё выбирает книгу или другой процесс строит индекс, несовместимая операция завершается понятным сообщением «индекс занят» с предложением повторить запуск, без повреждения старого индекса. Обновление не должно пытаться заменить открытый читателем SQLite-файл: это существенно для Windows. Совместимые читатели могут работать одновременно; изменение индекса посреди выбора запрещено на всех трёх ОС.

Все временные дескрипторы закрываются перед переименованием, заменой или удалением. Ошибка ОС при атомарной замене сохраняет старый индекс и сообщается пользователю; операции удаления старого индекса перед заменой запрещены.

Полная пересборка отражает добавленные книги, изменения автора и названия, изменения `DEL`, исчезнувшие записи и целые удалённые INP. Не требуется отслеживать их отдельными операциями.

При ошибке, нехватке места или отмене старый индекс сохраняется. Текущий поиск завершается с диагностикой, а не продолжает работу по устаревшим данным молча. После аварийного завершения следующий запуск может удалить только однозначно принадлежащие утилите временные файлы, удерживая блокировку.

Изменение содержимого ZIP без изменения INPX не вызывает пересборку: наличие выбранного ZIP и файла проверяется непосредственно перед извлечением. Не заявляется поддержка одновременной записи в ZIP во время извлечения; такие ошибки обрабатываются без публикации результата.

## 8. Поиск

Нормализация: Unicode NFKC, `casefold()`, замена `ё` на `е`. Исходный текст для отображения не изменяется. Запрос разбивается на последовательности букв и цифр; пунктуация является разделителем.

Все слова запроса обязательны, каждое ищется как префикс слова в авторе или названии. Например, `булг мастер` может найти Булгакова и «Мастер и Маргарита». Последовательность слов не обязана совпадать, слова могут находиться в разных полях.

Используется SQLite FTS5 с `unicode61` и отключённым удалением диакритики; входной текст нормализуется приложением. FTS-выражение строится только из экранированных токенов, а SQL-параметры связываются штатно. Пользовательские SQL и синтаксис операторов FTS не исполняются.

Сортировка: точное совпадение нормализованного названия с нормализованным запросом выше остальных; затем релевантность FTS5; затем автор, название, путь ZIP и имя файла для устойчивого порядка. Страницы и номер выбранной книги относятся к одному открытому снимку индекса. Каталог не обновляется посреди выбора.

## 9. Безопасное извлечение

1. По выбранной строке получить сохранённые относительный путь ZIP и точное имя FB2; не пересчитывать их по видимому номеру после обновления индекса.
2. Проверить, что разрешённый путь ZIP остаётся внутри `lib.rus.ec/`, в том числе при наличии символических ссылок.
3. Проверить наличие ZIP и единственного точного совпадения имени файла внутри. Не выбирать соседнее издание или похожее имя автоматически.
4. Сформировать безопасное имя `<автор> — <название> [<FILE>].fb2`: убрать разделители пути, управляющие символы и запрещённые Windows-символы `< > : " | ? *`, исключить зарезервированные имена устройств Windows и завершающие пробелы/точки, ограничить длину с сохранением идентификатора и расширения; при пустых метаданных использовать безопасный идентификатор. Правила применяются одинаково на всех ОС, чтобы извлечённые имена были переносимыми.
5. Потоково прочитать выбранный файл через `zipfile` в собственный временный файл, завершить чтение с проверкой CRC и закрыть файл.
6. Опубликовать готовый файл атомарно, без перезаписи существующего файла, включая гонку с другим процессом. Если файловая система не поддерживает необходимую безопасную операцию, сообщить об ошибке, не ослабляя гарантии.
7. При совпадении имени оставить существующий файл неизменным и сообщить пользователю; для другого пути можно повторить поиск с `--output`.

Не использовать `extractall`, не создавать пути из имён ZIP-записей. Отсутствие архива или member, дубликаты member, неподдерживаемое сжатие, шифрование, CRC-ошибка, нехватка места, запрет записи и отмена не должны оставлять опубликованный частичный FB2.

Наличие всех новых ZIP не является условием импорта INPX: книга может быть видна в поиске до завершения копирования её архива, но извлечение сообщает, какой именно файл недоступен.

Публикация без перезаписи скрыта за одним платформенным контрактом. Проверка `exists()` с последующим обычным переименованием не обеспечивает контракт: на POSIX это может перезаписать файл при гонке. Платформенный слой выбирает атомарную операцию no-replace для конкретной ОС/файловой системы, без общей зависимости от Linux `renameat2`. Коллизии регистра и нормализации Unicode на case-insensitive файловых системах также считаются конфликтами, а не разрешением перезаписи.

Извлечение должно проходить проверки на обычных локальных файловых системах ext4 в Linux, NTFS в Windows и APFS в macOS. Это не запрет иных файловых систем: при наличии необходимых гарантий они работают через тот же контракт. Если конкретная файловая система их не предоставляет, операция завершается диагностикой без ослабления безопасности. Сетевые диски и файловые системы с неподдерживаемой семантикой блокировок/атомарности не входят в гарантируемую матрицу первой версии. При ограничении полной длины пути Windows сообщается необходимость выбрать более короткий каталог; приложение не меняет системные политики.

## 10. Границы компонентов

- CLI: аргументы, сообщения, страницы, выбор и коды завершения.
- Конфигурация: нативные пути состояния Linux/Windows/macOS, проверка и сохранение настроек.
- Читатель INPX: структура, поток строк, валидация и преобразование записей.
- Индексатор: отпечаток источника, блокировка, построение и публикация SQLite.
- Поиск: нормализация, FTS-запросы, сортировка и выдача страниц.
- Извлечение: проверка путей и ZIP, безопасное имя, потоковое чтение и публикация.
- Платформенный слой: пути состояния, общая/исключительная файловая блокировка, атомарная публикация no-replace и необязательные платформенные измерения ресурсов. Общие компоненты не импортируют безусловно `fcntl`, `msvcrt`, `pty` или `resource`.

Компоненты передают типизированные записи и предметные ошибки. UI не разбирает INPX, индексатор не извлекает книги, извлечение не меняет поисковый индекс. Стандартной библиотеки Python достаточно; внешние `unzip`, Wine и MyHomeLib не требуются.

Сборка/релиз — отдельный слой над тем же entry point. Пользовательские файлы не ищутся и не сохраняются относительно каталога распаковки PyInstaller или `sys.executable`; упаковка не должна менять правила доступа к библиотеке и XDG/AppData/Library-пути.

Платформенные части используют условные импорты и штатные системные API, доступные через стандартную библиотеку. Кириллица корректно читается из INPX и отображается в нативном терминале; отсутствие возможности вывести отдельный символ не должно приводить к повреждению файлов или traceback. ANSI-управление терминалом не является условием работы нумерованного интерфейса.

## 11. Проверки и критерии приёмки

Автоматические тесты используют маленькие синтетические INPX и ZIP во временных каталогах, не меняя настоящую библиотеку:
- Чтение полей по `structure.info`, изменение порядка и дополнительные поля, BOM, разные переводы строк, несколько авторов и пустые необязательные значения.
- Объединение строк одного ZIP/member с разными сериями, устранение полностью одинаковых строк, сохранение списка серий и отказ при конфликтующих основных метаданных. Разные файлы одинакового произведения остаются отдельными результатами.
- Отсечение `DEL`, отличного от `0`, и форматов, отличных от FB2; диагностирование повреждённых и неоднозначных строк.
- Кириллица, регистр, `ё`/`е`, NFKC, префиксы, несколько обязательных слов, пунктуация и отсутствие SQL/FTS-инъекции.
- Стабильная сортировка, переход между страницами, выбор допустимого номера, неверный ввод, EOF и отмена.
- Первый запуск, повторный запуск без пересборки, принудительная пересборка и смена библиотеки.
- Добавление, изменение и исчезновение записей и INP, изменение `DEL`, смена версии схемы, повреждённый индекс.
- Сбой и отмена построения, конкурирующий индексатор и изменение INPX во время импорта; старый индекс остаётся пригодным.
- Отсутствующий ZIP или member, дубликат member, повреждение ZIP/CRC, traversal и выход через симлинк.
- Безопасное длинное имя, конфликт имени и конкурентное создание файла, ошибки записи и отсутствие безопасной публикации на файловой системе.
- Сквозной сценарий `setup` → `search` → выбор → извлечение; сравнение байтов извлечённой книги с источником.
- Проверка путей состояния для всех ОС, Windows-имён устройств/запрещённых символов, кириллических путей с пробелами, drive-relative/UNC-выходов и симлинков/junction при поддержке ОС.
- Проверка общих и исключительных блокировок настоящими процессами, освобождения после аварии, отказа обновления при активном читателе и успешного обновления после закрытия его SQLite-соединения.
- Проверка атомарной публикации, конфликтов регистра и Unicode-нормализации с учётом реальной семантики файловой системы, а не только mock-тестами API другой ОС.

Автоматическая матрица CI обязательна: нативные Linux, Windows и macOS, CPython 3.11 и 3.14. На всех трёх ОС выполняются общие тесты, установка entry point, импорт, поиск, обновление INPX, выбор и извлечение на синтетической библиотеке. Проверки, специфичные для конкретной ОС, исполняются на ней; mock-тесты Windows на Linux не заменяют реальный Windows-прогон. Нельзя пропускать весь сквозной сценарий Windows из-за отсутствия `pty`.

Дополнительно строится и проверяется каждый из четырёх portable-артефактов на собственной целевой архитектуре. Сборочная версия Python может быть одной фиксированной: тестировать несколько исходных версий Python не означает выпускать несколько вариантов одного артефакта. Smoke-проверка распакованного комплекта выполняет `--help`, настройку, импорт/обновление синтетического INPX, поиск, выбор номера и извлечение с проверкой байтов. Она запускает именно executable из архива в окружении без доступного системного Python и исходного checkout, с каталогом программы без разрешения на запись. Библиотека, временные файлы и пользовательское состояние находятся снаружи комплекта.

Отдельно проверяются сохранность разрешения на выполнение Linux/macOS после распаковки tar.gz, состав архива и отсутствие локальных данных, SHA-256, наличие корневых документов в исходном проекте, наличие `README.md`/`INSTALL.md` в артефактах и соответствие их команд реальной сборке. CI не публикует артефакт как проверенный, если smoke-тест его ОС/CPU не выполнен.

Для тестирования ввода общий UI получает потоки через внедрение зависимостей. Нативное TTY-поведение отдельно проверяется POSIX PTY в Linux/macOS и Windows console/ConPTY либо эквивалентным нативным harness; дополнительные инструменты harness допустимы только как тестовые зависимости и не становятся runtime-требованием. Время измеряется `perf_counter` на всех ОС. Пиковая память приводится в единой единице, если доступен платформенный измеритель; иначе поле равно `null` с пояснением, без обязательного импорта `resource` на Windows и без фиктивного нуля.

После автоматических тестов отдельно выполняется проверка на реальной библиотеке с индексом во временном выделенном каталоге: импорт, поиск известной книги, сверка ZIP/member и извлечение в отдельный тестовый каталог. Состояние INPX и ZIP не меняется.

На целевом компьютере измеряются время и пиковая память первичного импорта, время проверки SHA-256 и время поиска по готовому индексу. Целевой ориентир для отдельного поискового SQL-запроса — до 1 секунды; хеширование и построение измеряются отдельно. Если ориентир не достигнут, причина исследуется до объявления готовности. Обещаний о времени полной пересборки до измерений нет.

Первая версия принимается, когда выбранная книга извлекается байт-в-байт, обновление каталога корректно отражается в поиске, сбои не повреждают предыдущий индекс и готовые файлы, а исходная библиотека остаётся неизменной. Обязательны успешные нативные прогоны Linux, Windows и macOS и smoke-тест каждого portable-артефакта без системного Python; проверка только на текущем Linux-компьютере недостаточна для заявления о кроссплатформенной готовности. В корне проекта присутствуют проверенные `README.md`, `BUILD.md`, `INSTALL.md`, `AGENTS.md`.
